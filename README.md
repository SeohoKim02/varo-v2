# Varo V2

편의점 냉장·냉동 상품의 **악성(과잉/임박) 재고를 어디로 얼마나 옮길지** 판단하도록 돕는
Streamlit 기반 재고 의사결정 프로그램입니다. 재고 담당자가 엑셀 데이터를 넣으면, 실행 가능한
이동 후보를 만들고 VHS 점수로 우선순위를 매겨 **추천 이동(출발 점포 → 도착 점포, 수량, 경로)**
을 제시합니다.

> 이 문서는 실제 사용자를 위한 시작 안내입니다. 알고리즘 원리는 [`docs/ALGORITHM.md`](docs/ALGORITHM.md),
> 데이터 형식은 [`docs/DATA_SCHEMA.md`](docs/DATA_SCHEMA.md), 검증 방식은
> [`docs/VALIDATION.md`](docs/VALIDATION.md), 단계별 사용법은 [`docs/USER_GUIDE.md`](docs/USER_GUIDE.md)
> 를 참고하세요.

## 해결하는 문제

- 어느 점포에 재고가 과잉이고 어느 점포에 부족한지 한눈에 보기 어렵다.
- 폐기 위험이 큰 재고를 이동으로 살릴 수 있는지, 이동 비용 대비 효과가 있는지 판단이 필요하다.
- "그래서 무엇을 옮겨야 하는가"에 대한 실행 가능한 추천이 필요하다.

Varo V2는 이 판단을 **VHS(Varo Hybrid Score) 다기준 점수**로 종합해 우선순위를 제시합니다.
Greedy(단순 기준선)·Pareto(비지배 검증)·DQN(선택형 참고)은 비교·검증 보조 수단이며,
**최종 추천과 순위는 항상 VHS가 담당**합니다.

## 설치

- Python 3.11 권장
- 기본 의존성에는 앱 실행 패키지와 실행 이력용 PostgreSQL 드라이버가 포함됩니다. `torch`는 DQN 학습 시에만 선택 사항입니다.

```bash
python -m pip install -r requirements.txt
# DQN 학습을 직접 실행할 때만 추가 (없어도 앱은 정상 동작):
python -m pip install torch
```

## 실행

```bash
python -m streamlit run app_v2.py --server.headless true --server.port 8501
```

브라우저에서 `http://localhost:8501` 을 엽니다.

## 실행 이력 저장 설정

- 별도 설정이 없으면 `runtime_data/varo_execution_history.sqlite3`에 로컬 저장합니다.
- 운영 환경에서 `VARO_HISTORY_DATABASE_URL`을 설정하면 PostgreSQL 서버 저장을 사용합니다.
- 서버 DB를 명시한 뒤 연결이 실패하면 임시 SQLite로 우회하지 않고 실행 이력 기능만 저장 실패로 처리합니다.
- 실제 URL·비밀번호는 코드나 Git에 넣지 말고 배포 환경의 비밀 설정에만 저장합니다.

Streamlit Community Cloud에서는 앱 설정의 Secrets에 `VARO_HISTORY_DATABASE_URL`을 **최상위 키**로
등록합니다. 최상위 secret은 환경변수로 전달되므로 저장 service가 Streamlit에 직접 의존하지 않습니다.
이 작업은 코드 준비만 포함하며 실제 Cloud secret이나 운영 DB는 변경하지 않습니다.

기존 SQLite 이력을 PostgreSQL로 옮길 때는 먼저 쓰기 없는 검사를 실행한 뒤 명시적으로 적용합니다.

```bash
python tools/migrate_execution_history.py --dry-run
python tools/migrate_execution_history.py --apply
```

`--source`를 생략하면 기본 SQLite 위치를 사용합니다. 이관은 원본 SQLite를 읽기 전용으로 다루며,
이미 서버에 있는 계획은 중복으로 집계하고 다시 생성하지 않습니다.

배포 전에는 저장소 상태를 먼저 점검합니다. 연결 URL이나 비밀번호는 출력하지 않습니다.

```bash
python tools/check_execution_history_db.py       # backend / 연결 / TLS / 스키마 버전·구조
```

실제 PostgreSQL 서버에 대한 통합 검증은 **비운영 staging DB**를 지정했을 때만 수행합니다.
`VARO_HISTORY_TEST_DATABASE_URL`이 없으면 `PostgreSQL staging URL not configured.`를 출력하고
미검증 상태로 종료합니다.

```bash
python tools/validate_postgresql_history.py      # 연결·스키마·쓰기·동시성·rollback·재연결·내보내기
```

환경변수, TLS, 백업/복원, health check, 장애 시 행동, 성능·규모 한계는
[`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md)에 정리되어 있습니다.

## 기본 사용 순서

앱을 열면 **재고 운영** 화면이 나옵니다. 재고 재배치 판단은 이 한 화면에서 끝납니다.

1. **데이터 확인** — 왼쪽 "상태"에서 지금 적용된 데이터와 미확보 항목을 봅니다.
   비어 있으면 "데이터 관리"로 이동해 샘플을 적용하거나 엑셀을 올립니다.
2. **분석 실행** — 데이터가 적용되면 같은 화면에서 바로 **"분석 실행"**을 누릅니다.
3. **오늘 권장 이동 확인** — 오른쪽에서 출발 → 도착, 상품, 실행 수량, 경로, 예상 순효과, 이유, 위험을 봅니다.
4. **네트워크에서 경로 이해** — 가운데 네트워크에서 점포·DC와 오늘의 이동 경로를 봅니다.
5. **다른 이동 선택** — 왼쪽 **"실행 계획"** 목록에서 한 번 클릭하면 네트워크·오른쪽 패널·아래 탭이
   모두 그 이동으로 바뀝니다. 계획이 50건이어도 목록 높이는 그대로입니다.
6. **대안 / 세부 / 검증 확인** — 아래 탭에서 대안 비교, 이동 세부 값, 검증 결과를 봅니다.
7. **계획 기록** — 오른쪽 패널 아래 **"이 계획 기록"**을 누르면 지금 계획이 기록됩니다.
   실제 실행 결과(실행/일부 실행/미실행, 실제 수량·비용·절감)는 아래 **"실행 이력"** 탭에서 입력합니다.
8. **내보내기** — 왼쪽 실행 계획 목록 아래 **"내보내기"**를 펼쳐 CSV 또는 Excel을 내려받습니다.
   화면에 보이는 실행 계획이 그대로, 실행 수량 기준으로 나갑니다.

사용자에게 보이는 메뉴는 네 개입니다.

| 메뉴 | 하는 일 |
| --- | --- |
| **재고 운영** | 결정과 실행. 위 1~8의 판단·기록·**실행계획 내보내기**. 앱의 첫 화면입니다. |
| **데이터 관리** | 입력 데이터 준비. 등록 · 검사 · 오류 확인 · 적용 · 원본 확인 (**데이터 오류 목록 CSV**) |
| **분석 및 검증** | 연구와 신뢰성 검증. 결론 먼저, 그 아래 벤치마크·민감도·안정성·DQN, 끝에 **연구용 내보내기** |
| **운영 시뮬레이션** | 이동 흐름 이해. 추천 경로의 애니메이션 |

내보내기도 화면마다 주인이 하나입니다.

| 파일 | 어디서 | 무엇을 위해 |
| --- | --- | --- |
| 실행계획 **CSV / Excel** | 재고 운영 → 내보내기 | 현장에서 실행할 계획(실행 수량 기준) |
| **데이터 오류 목록 CSV** | 데이터 관리 (검사 중 / 적용 데이터) | 원본 데이터를 고치기 위한 문제 목록 |
| **상세 분석 결과 Excel** · **검증 결과 Excel** · 제외된 이동 검토 CSV · DQN 학습 결과 | 분석 및 검증 | 연구·캡스톤·학회·benchmark |
| **실행 기록 CSV** | 재고 운영 → 실행 이력 | 계획 대비 실제 결과 누적(calibration) |

같은 파일을 두 화면에서 다른 이름으로 다시 제공하지 않습니다.

일상 작업은 **재고 운영 한 화면에서 끝납니다.** 예전의 추천 실행·경로 상세 화면이 하던 일(목록, 필터,
세부 값, CSV·Excel 다운로드)은 모두 이 화면 안으로 들어왔습니다. 두 route는 호환을 위해 그대로 두었고,
사이드바 **보조 화면**(접힘) 안에서 **연구용 목록**(전체 목록·점수 비교)과 **경로 지도**(지도·이동 단계)로
열 수 있습니다. 일상 작업에는 필요하지 않습니다.

## 재고 운영 화면 구성

```
상단   VARO V2 · 데이터 상태 · 분석 상태
KPI    오늘 실행 이동 · 총 이동 수량 · 예상 순효과 · 주의 필요
왼쪽   상태 / 필터(상품·순효과 + 접힘 "추가 조건": 출발·도착·경로 유형·주의) / 실행 계획 목록 / 내보내기(접힘)
중앙   점포 · DC · 이동 경로 네트워크 (출발 왼쪽 · 경유 DC 가운데 · 도착 오른쪽,
       DIRECT 실선, VIA_DC 점선, 선택 경로 강조)
오른쪽 오늘 권장 이동 — 출발→도착, 상품, 실행 수량, 경로, 예상 순효과, 이유, 위험, "이 계획 기록"
하단   대안 비교 · 세부 정보 · 검증 · 실행 이력
```

- 이동 선택은 **왼쪽 "실행 계획" 목록 한 곳**에서만 합니다. 높이가 고정된 스크롤 목록이라 계획이
  8건이든 50건이든 세로로 늘어나지 않고, 어느 이동이든 **한 번의 클릭**으로 고릅니다. 고르는 순간
  네트워크 강조 · 오른쪽 패널 · 아래 네 탭이 **모두 같은 이동**으로 바뀝니다
  (선택 상태는 앱 전체에서 하나의 `selected_route_id`입니다).
- 화면에 크게 보이는 수량은 원래 권장 수량이 아니라 **실제 실행 수량**입니다. 여러 이동이 같은 출발
  재고를 쓰면 수량이 조정되며, 그 사실을 한 줄로 알려줍니다.
- 기본 네트워크는 **현재 실행계획**만 그립니다. "선택한 이동"으로 좁히거나 "전체 네트워크"로 넓힐 수 있습니다.
- 실행계획이 많아 점포가 늘어나도 **지금 선택한 이동**은 항상 크게, 상태와 실행 수량까지 읽을 수 있게
  표시됩니다. 나머지 점포는 맥락으로 남고, 상태는 작은 도형으로 바뀝니다.

## 실행 계획 내보내기

왼쪽 실행 계획 목록 아래 **"내보내기"**(접힘)에서 **CSV**와 **Excel**을 내려받습니다. 페이지를 옮길
필요가 없습니다.

- 내용은 **실행 계획**입니다. 수량은 후보 권장량이 아니라 **실행 수량(planned_qty)**이고, 순서는
  Varo가 정한 실행 우선순위입니다(화면 필터가 걸려 있으면 화면에 보이는 그대로).
- 열: 순위 · 출발 점포 · 도착 점포 · 상품 · 실행 수량 · 경로 · 경유 DC · 예상 비용 · 예상 절감 ·
  예상 순효과 · 안정성 · 주요 주의 · 데이터 기준.
- 내부 식별자(route_id 등)·점수 구성요소·solver 값은 들어가지 않습니다. 연구용 상세 export는
  **분석 및 검증** 화면(검증 결과 탭 → 내보내기)에 있습니다. 데이터 관리에는 두지 않습니다.
- 내보낼 실행계획이 없으면 빈 파일을 만들지 않고 "내보낼 실행계획이 없습니다."라고 알립니다.
  파일 생성이 실패하면 "파일을 만들지 못했습니다."만 보여주고 내부 오류는 화면에 올리지 않습니다.
- 아직 수집 중인 실제 거리·이동 시간·차량 용량·실제 운송비는 **0으로 채우지 않습니다.** 값이 없는
  칸은 비워 두고, `데이터 기준` 열에 "실제 운송정보 미확보"로 남깁니다.
- 파일명: `varo_execution_plan_YYYYMMDD.csv` / `.xlsx`. CSV는 UTF-8 BOM이라 Excel에서 한글이
  깨지지 않습니다.

## 재고 운영 상태 표시

재고 운영 화면은 현재 상태에 따라 **하나의 상태와 다음 행동 하나**만 보여줍니다. 실행계획이 있을 때만
KPI·네트워크·실행 패널이 나타나며, 실행 전이나 계산 실패 상태에서 수치를 0으로 채우지 않습니다.

| 상태 | 재고 운영 화면 표시 | 다음 행동 |
| --- | --- | --- |
| 데이터 없음 | "데이터를 준비하세요" | 데이터 불러오기 → 데이터 관리 |
| 검사한 데이터 있음(미적용) | "검사한 데이터를 적용하세요" | 데이터 적용 → 데이터 관리 |
| 사용 불가 업로드(적용 데이터 없음) | "데이터를 수정해야 합니다" (핵심 오류) | 문제 확인 → 데이터 관리 |
| 데이터 적용 완료·분석 전 | "분석 실행 준비가 완료되었습니다" | **분석 실행** (같은 화면에서) |
| 데이터가 바뀜 | "현재 결과가 최신 데이터 기준이 아닙니다. 다시 분석하세요." | **분석 실행** (같은 화면에서) |
| 실행할 이동 없음 | "추천할 이동이 없습니다" (제외 원인 + 제외 후보 목록) | 원본 데이터 수정 |
| 실행계획 있음 | KPI + 네트워크 + 실행 계획 목록 + 오늘 권장 이동 | 세부 정보 확인 / 실행계획 기록 |

**이미 적용된 정상 데이터가 있으면**, 새로 올린 파일이 오류·정상 어느 상태든 현재 결과를 유지하고
"검사 완료된 새 데이터가 있습니다"라는 짧은 안내만 표시합니다(적용은 데이터 관리에서 직접).
새 데이터를 실제로 **적용**하면 이전 추천·KPI는 초기화되며, 분석 실행 후 새 결과가 만들어집니다.

## 아직 확보되지 않은 데이터

실제 물류 데이터 수집이 진행 중이므로, 화면은 값의 성격을 구분해 보여줍니다.

| 표시 | 뜻 |
| --- | --- |
| 실제 관측 | 적용된 데이터에 실제로 들어 있는 값 (판매·재고, 기록된 실행 결과) |
| 기준값 | 데이터에 입력되어 계산에 쓰이는 값 (경로·거리·시간·이동비용) |
| 추정 | 다른 값에서 계산한 값 (안전재고 기준이 없을 때의 추정) |
| 미확보 | 아직 수집되지 않은 값 |

실제 도로 거리, 실제 이동 시간, 차량 용량, 실제 청구 운송비, 실제 거점간 이동이력은 현재 **미확보**이며,
UI를 채우기 위해 임의의 값이나 0으로 만들지 않습니다. 재고 운영 하단 **"세부 정보"** 탭의
**운송 정보** 표(이동 한 건 기준)와 **데이터 상태** 표(데이터 전체 기준)에서 항목별 상태를 확인합니다.
파일에 참고용 입력값이 있으면 값 칸은 `미확보`로 두고 설명 칸에 "데이터에 입력된 값 4.7km는 계산에
사용했지만, 실제 값은 아직 수집 중입니다"처럼 적습니다.

수집이 끝나면 연결할 지점은 `services/workspace_view.LOGISTICS_FIELDS`에 이름으로 적혀 있습니다
(`actual_distance_km`, `actual_travel_time_min`, `actual_vehicle_capacity`, `actual_transport_cost`).
후보가 그 필드를 싣기 시작하면 UI 변경 없이 실제 값이 표시됩니다.

## 데이터 업로드 방법

- 상단 데이터 바의 업로드 위젯에 파일을 올립니다. 지원 형식: **`.xlsx` · `.xls` · `.csv`**.
  지원하지 않는 형식·빈 파일·손상된 파일은 즉시 짧은 안내로 차단됩니다(오류 로그만 내부 보관).
- **CSV는 표 하나만 담을 수 있어** 분석에 필요한 여러 시트(점포·상품·재고·경로)를 만들 수 없으므로,
  여러 시트가 있는 Excel 워크북을 권장합니다(CSV는 안전하게 읽되 Excel로 안내).
- 컬럼명은 한글/영문 별칭으로 표준 컬럼에 자동 매핑됩니다(`services/column_aliases.py`).
- **추천 결과 시트가 없으면** 재고·경로 데이터로 후보를 자동 생성합니다(rule-based).
- 필수 컬럼·시트가 부족하면 추천 계산을 **보류**하고, 데이터 관리의 "데이터 점검"에서 어느 행·컬럼을
  고쳐야 하는지 보여줍니다(문제 목록 CSV 내려받기 가능).
- 필요한 컬럼과 형식은 [`docs/DATA_SCHEMA.md`](docs/DATA_SCHEMA.md)에 정리되어 있습니다.

## 파일 선택 → 검사 → 적용 → 추천 실행 (2단계 적용)

파일을 올렸다는 이유만으로 현재 데이터가 바뀌지 않습니다. **검사와 적용은 별도 단계**입니다.

1. **파일 선택** — 상단 데이터 바에서 `.xlsx`/`.xls`/`.csv`를 올립니다. 파일을 읽어 검사만 하고,
   현재 사용 중인 데이터와 추천 결과는 그대로 둡니다("검사 중인 데이터"로 표시).
2. **검사 결과 확인** — 데이터 관리에서 파일명·시트·전체/분석 사용/오류/경고/제외 행, 주요 문제,
   미리보기, 적용 가능 여부를 확인합니다.
3. **데이터 적용** — 사용자가 직접 누릅니다. 정상은 **"이 데이터 사용"**, 유지 경고만 있으면
   **"확인 후 이 데이터 사용"**, 실제 제외 행이 있으면 **"문제 행을 제외하고 사용"**입니다.
   구조 오류이거나 제외 후 재검증에 실패하면 적용 버튼이 없습니다. 적용해야 비로소 현재 데이터가
   교체되고 이전 추천·후보·경로·시뮬레이션 결과가 초기화됩니다(같은 데이터면 불필요한 초기화 없음).
4. **분석 실행** — 적용이 끝나면 재고 운영 화면의 **"분석 실행"** 버튼을 누릅니다(예전 화면의
   화면에도 같은 버튼이 남아 있습니다). 업로드 적용만으로 VHS·Greedy·Pareto 분석이나 DQN 학습이
   자동 실행되지 않습니다.

안전하게 분리할 수 있는 개별 행만 원본 행 번호로 제외합니다. 필수 시트·컬럼 누락, 별칭 충돌,
핵심 테이블 소실처럼 파일 구조를 신뢰할 수 없는 오류는 자동으로 무시하지 않으며 파일 전체를 차단합니다.
제외 전에는 적용 예정 행과 제외 이유를 확인하고 문제 목록 CSV를 내려받을 수 있습니다.

> 기본 샘플(데이터 관리의 "선택한 샘플 적용")은 버튼 클릭이 곧 적용이므로 한 번에 적용됩니다.

## 데이터 관리 화면

데이터 관리 페이지는 재고 운영 화면과 **같은 상태 문구**를 쓰며, 현재 앱에 적용된 데이터("현재 사용 중 데이터")와
아직 적용되지 않은 업로드("검사 중인 데이터")를 분명히 구분합니다.

- 새 파일이 오류·정상·경고 어느 상태든, **적용 버튼을 누르기 전까지** 기존 정상 데이터와 추천은 유지됩니다.
- 새 파일이 사용 불가라도 재고 운영 화면은 현재 적용 데이터로 계속 동작합니다(전체 앱이 멈추지 않음).
  화면에는 "검사 완료된 새 데이터가 있습니다"라는 짧은 안내만 표시됩니다.
- 사용 불가 데이터에는 적용 버튼이 없고, 문제 행·수정 방법과 "검사 중 데이터 오류 목록 CSV"를 제공합니다.
  적용이 끝난 데이터의 문제는 "적용 데이터 오류 목록 CSV"로 내려받습니다. 오류가 0건이면 빈 CSV를
  만들지 않고 버튼 자체가 나오지 않습니다.
- 이 화면은 **입력 데이터 전용**입니다. 추천 결과·실행계획·연구 분석 결과는 내보내지 않고,
  화면 끝에서 분석 및 검증으로 안내만 합니다.
- 적용에 실패하면 기존 사용 데이터와 검사 결과를 그대로 보존하고 짧은 안내만 보여줍니다.
- "검사 중인 데이터 취소"는 검사 결과만 지우고 현재 데이터는 유지합니다.
- "현재 데이터 초기화"는 앱에 적용된 데이터와 결과만 비우며, 사용자의 원본 파일은 삭제하지 않습니다.

## 추천 결과 읽는 법

각 추천은 다음을 보여줍니다.

- **출발 → 도착 점포, 상품, 권장 이동 수량, 경로 유형(DIRECT / VIA_DC), 예상 순효과**
  (예상 순효과 = 예상 절감액 − 이동 비용. 절감액과 이동 비용 각각은 후보 상세에서 확인)
- **실행 상태**: `추천 가능` / `데이터 확인 필요` / `이동 불가`(제외됨)
- **추천 안정성**: `안정` / `검토 필요` / `변동 가능성 큼` (판단 기준이 바뀌어도 순위가 유지되는지)
- **추천 신뢰도**: `높음` / `보통` / `낮음` / `계산 불가` — 성공 확률이 아니라 상대적 신뢰 표시
- **짧은 추천 이유**(최대 3개): 과잉/부족·폐기 위험·비용 대비 효과·경로 조건 등 실제 계산 근거
- **이동 수량 근거**: 무엇이 수량을 제한했는지 한 줄로(예: "도착 점포 부족량을 기준으로 12개 이동을 권장합니다.")
- **원본 데이터 확인**(접힘): 판단에 쓰인 원본 파일·시트·행·입력값. 데이터 관리 문제 목록과 같은 행을 가리킵니다.
- **실행 계획에서 제외된 이동**(접힘): 사라지지 않고 상태·핵심 이유·원본 위치와 함께 확인합니다.
  전체 목록 CSV는 분석 및 검증 화면 한 곳에서만 내려받습니다(같은 파일을 여러 화면에 두지 않습니다).

값이 계산되지 않으면 `-`, `데이터 없음`, `확인 필요`, `계산 불가`로 **정직하게 표시**합니다.
없는 값을 0이나 정상으로 위장하지 않습니다.

## DQN은 선택형 보조 기능입니다

- DQN은 **자동 실행되지 않습니다.** 분석 및 검증 → DQN 학습 탭에서 버튼을 눌렀을 때만 학습/추론합니다.
- DQN 결과는 **정상 상태 + 현재 데이터 일치 + 안정성 통과**일 때만 낮은 비중으로 참고 반영되며,
  최종 추천과 순위는 언제나 VHS가 결정합니다.
- `torch`가 없으면 "실행 환경 필요"로만 표시하고 가짜 결과를 만들지 않습니다.

## 현재 지원 범위

- 기본 화면: **재고 운영**(상태·필터·실행 계획 목록 · 네트워크 · 실행 결정 패널 · 대안/세부/검증/이력)
- 사용자 메뉴: 재고 운영 · 데이터 관리 · 분석 및 검증 · 운영 시뮬레이션
- 보조 화면(접힘, route 유지): 연구용 목록 · 경로 지도 — 일상 작업에는 필요하지 않습니다
- 엑셀 업로드/샘플 적용, 실행 가능성 필터, VHS 추천·순위, Greedy·Pareto 비교 검증, 선택형 DQN
- 네트워크/이동 시뮬레이션(DIRECT 실선 · VIA_DC 점선, DC01/DC02 구분)

### 화면 설계 메모 (개발자용)

재고 운영 화면은 결과 중심 single-workspace 상호작용 패턴 — 한 화면에서 대상·시각 모델·결과·대안을 함께
두고, 페이지 이동 없이 판단을 끝내는 구성 — 을 참고해 **Varo의 다점포 재고 재배치 업무 흐름에 맞게
독립적으로 설계**했습니다. 화면 구성 요소, 상태 모델, 네트워크 표현, 텍스트는 모두 이 저장소의
실행계획 데이터 구조(`services/execution_plan.py`)에서 직접 도출한 것입니다.
구현은 `pages/workspace.py`, 뷰 모델은 `services/workspace_view.py`,
네트워크 렌더러는 `components/workspace_network.py`에 있습니다.

## 실제 사용 시 주의사항

- 샘플 데이터는 시연·검증용이며 실제 운영 데이터가 아닙니다.
- 일부 선택 컬럼이 없으면 해당 VHS 구성요소에 중립값(50)이 적용되어 분석이 제한될 수 있습니다.
- DQN 학습 샘플 팩(`Varo_DQN_training_samples_10pack`)은 이 저장소에 포함되지 않는 외부 데이터입니다.
- 카카오 지도·PDF·발표용 요약은 이 프로그램의 범위가 아닙니다.
