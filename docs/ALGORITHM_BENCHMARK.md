# Varo V2 알고리즘 검증 (`vhs-2.1`)

이 문서는 홍보 자료가 아니라 **측정 기록**입니다. 아래 수치는 모두
`tools/run_algorithm_benchmark.py`와 `tools/run_operational_validation.py`가 익명 운영 데이터에서
실제로 만들어낸 값이고, 결과가 좋게 보이도록 입력을 손보지 않았습니다.

사용 안내는 [`docs/USER_GUIDE.md`](USER_GUIDE.md), 계산 흐름은 [`docs/ALGORITHM.md`](ALGORITHM.md),
데이터 검증은 [`docs/OPERATIONAL_VALIDATION.md`](OPERATIONAL_VALIDATION.md)에 있습니다.

측정 환경: Windows 10 / Python 3.11.0, 단일 데스크톱.

---

## 1. 문제 정의

여러 점포와 2개 DC로 이루어진 네트워크에서, **어떤 상품을 어느 점포에서 어느 점포로 몇 개
보내야 하는가**를 정한다. 각 후보 이동은 다음을 동시에 만족해야 한다.

- 실행 가능해야 한다(재고·경로·수량이 실제로 성립)
- 비용을 빼고도 남아야 한다
- 출발지의 과잉을 줄이고 도착지의 부족을 채워야 한다
- 이동 후에 새로운 문제(출발지 결품, 도착지 과잉)를 만들지 않아야 한다
- 수요가 흔들려도 판단이 뒤집히지 않아야 한다

## 2. 후보 생성

추천 입력 시트가 있으면 그 행이 후보가 되고, 없으면 재고·경로에서
`services/candidate_generator.py`가 규칙 기반으로 후보를 만든다(유통기한·초과재고·도착지 수요·
경로 가능성·예상 절감액). 후보 생성 단계에서는 **모든 DC를 평가**해 가장 저렴한 경유 경로를
고른다 — DC 목록의 첫 번째 DC만 쓰지 않는다.

## 3. Hard Constraint (위반하면 후보에서 제거)

점수를 깎아 하위로 밀지 않고 **후보에서 뺀다**. `services/feasibility.py`.

| 조건 | 코드 |
|---|---|
| 출발지 = 도착지 | `same_source_target` |
| 이동 수량 ≤ 0 또는 계산 불가 | `invalid_quantity` |
| 경로 유형이 DIRECT/VIA_DC가 아님 | `no_route` |
| VIA_DC인데 경유 DC 없음 | `via_dc_missing_dc` |
| 이동 수량 > 출발 점포 재고 | `quantity_exceeds_stock` |
| 이동 비용이 음수 | `negative_cost` |
| **예상 효과 ≤ 이동 비용 (순효과 ≤ 0)** | `non_positive_net_benefit` |
| 동일 (상품·출발·도착) 중복 후보 | `duplicate` |

`non_positive_net_benefit`은 이번에 hard로 옮긴 항목이다. 근거: 비용보다 효과가 작은 이동을
상위에 노출하면 운영자가 손해 보는 실행을 하게 된다. **다만 "계산할 수 없음"은 hard가 아니다** —
절감액이나 비용을 못 구하는 경우는 `데이터 확인 필요`(soft)로 남긴다. "모른다"와 "손해다"는
다르게 다뤄야 하기 때문이다.

## 4. Soft Preference (추천은 가능하되 점수·표시에 반영)

| 조건 | 처리 |
|---|---|
| 비용/절감액을 계산할 수 없음 | `데이터 확인 필요` 표시 |
| 이동 후 출발 재고가 안전재고 아래 | `데이터 확인 필요` + `이동 후 위험` 점수 하락 |
| 도착 필요량 대비 과다 이동 | `데이터 확인 필요` + `이동 후 위험` 점수 하락 |
| 이동 비용·시간이 상대적으로 큼 | `이동 부담` 점수 하락 |
| 수요 변동이 큼 | `수요 안정성` 점수 하락 + 화면 상태 표시 |

같은 사실이 hard와 soft 양쪽에서 이중으로 처리되지 않는다. 두 계층이 읽는 숫자는
`services/decision_metrics.py`가 **한 번만** 계산한다.

## 5. VHS 구성요소

각 구성요소는 서로 다른 의사결정 질문 하나에 대응한다. 개수를 늘리는 것이 목적이 아니라
**중복과 순환을 없애는 것**이 목적이었다.

| 구성요소 | 질문 | 계산 | 정규화 |
|---|---|---|---|
| 예상 순효과 | 비용을 빼고도 남는가 | `expected_saving − estimated_cost` | 후보 집합 내 winsorized min-max |
| 재고 균형 | 출발지 과잉을 실제로 줄이는가 | `min(수량 / 이동가능량, 1)` | 절대 비율 (0~100) |
| 폐기 위험 | 폐기·악성재고를 줄이는가 | 유통기한(역방향) 0.6 + 악성재고 0.4 | winsorized min-max |
| 수요 적합도 | 도착지 부족을 채우는가 | `min(수량 / 부족량, 1)` | 절대 비율 (0~100) |
| 이동 부담 | 거리·시간·비용 부담이 큰가 | 거리 0.35 + 시간 0.35 + 비용 0.30 (각각 역방향) | 축별 winsorized min-max |
| 실행 여건 | 거리 기준·시간창을 통과하는가 | cutline/time-window 상태 가감 | 0~100 고정 스케일 |
| 수요 안정성 | 수요가 흔들려도 유효한가 | `수요 표준편차 / 수요` (역방향) + 시나리오 상태 보정 | winsorized min-max |
| 이동 후 위험 | 새 문제를 만들지 않는가 | 출발 결품 폭 0.5 + 도착 과잉 폭 0.5 (각각 역방향) | winsorized min-max |
| DQN 참고 | (선택형) 학습 결과가 있으면 | 학습 결과가 정상일 때만, 낮은 비중 | 0~100 |

### 이전 구조에서 고친 것

1. **절감액 → 순효과.** 이전에는 총 절감액이 점수의 축이고 비용은 별도 페널티였다. 절감
   100,000 · 비용 90,000인 이동과 절감 100,000 · 비용 5,000인 이동이 비슷하게 평가될 수 있었다.
2. **Greedy 점수를 VHS에서 제거.** 기준선이 점수 안에 들어 있으면 "VHS vs Greedy" 비교가
   순환 논리가 된다.
3. **신뢰도 점수를 VHS에서 제거.** 신뢰도는 VHS 결과로부터 계산되는 하위 지표라 다시 VHS의
   입력이 되면 순환한다.
4. **프로모션 비교 제거.** 프로모션은 이 이동의 속성이 아니라 다른 행동이다.
5. **수요 불확실성·이동 후 위험 추가.** 이전에는 어느 구성요소에도 없었다.
6. **과다 이동 보상 제거.** 필요량보다 많이 보낼수록 점수가 오르던 방향 오류를 상한으로 고쳤다.

### 정규화와 극단값

- **Winsorized min-max**: 5~95 백분위로 clip한 뒤 0~100으로 스케일. 극단값 하나가 나머지 후보를
  몇 점 안에 뭉개는 문제를 막으면서 순서는 보존한다.
- **비율형 구성요소**(재고 균형·수요 적합도)는 후보 간 정규화를 쓰지 않는다. `min(a/b, 1)`은
  이미 절대 0~1이라 이상치에 구조적으로 안전하다.
- `NaN`/`±inf`는 스케일 경계가 되기 전에 제거하고, 값이 없으면 **중립 50**을 쓴다(0이 아니다).
- 스프레드가 0이면 전부 중립값. 계산 불가를 0점으로 위장하지 않는다.

### 가중치

`WEIGHT_BOUNDS` 안에서 컬럼 커버리지와 값의 변별력에 따라 자동 배분하고 합을 1로 맞춘다.
익명 운영 데이터에서 나온 실제 가중치:

| 순효과 | 재고 균형 | 폐기 위험 | 수요 적합도 | 실행 여건 | 이동 부담 | 이동 후 위험 | 수요 안정성 | DQN |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 0.276 | 0.147 | 0.125 | 0.114 | 0.102 | 0.100 | 0.071 | 0.065 | 0.000 |

## 6. Tie-break

동점일 때 DataFrame 행 순서에 의존하지 않는다. 아래 순서로 결정하며, 모두 실제 계산값이라
같은 입력은 항상 같은 순위를 만든다.

1. VHS 점수 (높은 쪽)
2. 예상 순효과 (큰 쪽)
3. 이동 비용 (낮은 쪽)
4. 이동 시간 (짧은 쪽)
5. 경로 단순성 (DIRECT < VIA_DC)
6. `route_id` (마지막 안정 키)

행 순서를 뒤집어도 순위가 같다는 것을 테스트로 고정했다.

## 7. 강건성 검증

VHS 가중치를 구성요소마다 ±30% 흔들어(운영 데이터 기준 16개 시나리오) 후보별로 측정한다.

- 기본 순위 · Top-1 유지율 · Top-3 유지율 · 평균 순위 · 최선/최악 순위 · 순위 변동 폭

상태 판정(후보 수에 비례하는 임계값):

| 상태 | 조건 |
|---|---|
| 안정 | 순위 변동 폭 ≤ max(1, 5% × 후보 수) |
| 검토 필요 | 순위 변동 폭 ≤ max(3, 15% × 후보 수) |
| 변동 가능성 큼 | 그 이상 |

1순위 후보가 일부 시나리오에서만 1위를 지키면(Top-1 유지율 < 0.8) 안정으로 판정하지 않는다.

**강건성은 순위를 바꾸지 않는다.** VHS가 순서를 정하고, 강건성은 그 순서를 얼마나 믿을 수
있는지만 알려준다. 자동 교체는 하지 않는다.

익명 운영 데이터(58건): 안정 27 · 검토 필요 29 · 변동 가능성 큼 2. 1순위 후보는 16개 시나리오
전부에서 1위를 유지했다.

## 8. 수요 불확실성

`demand_std`가 **실제로 있을 때만** 보수적/기준/공격적 세 시나리오(±1σ)를 만든다. 없으면
`계산 불가`로 두고 표준편차를 지어내지 않는다. 사용자 화면에는 `안정 / 확인 필요 / 변동 가능성 큼`
상태만 보이고 세부 값은 검증 출력에 남는다.

익명 운영 데이터: 안정 57 · 계산 불가 1.

## 9. Greedy 기준선

앱의 `greedy_rank`는 legacy `heuristic_optimizer`의 복합 점수라 비교 기준으로는 모호했다.
검증용으로 목적이 하나뿐인 기준선을 따로 정의했다(`services/greedy_baseline.py`).

> **절감액 우선 Greedy** — 예상 절감액이 큰 순서. 동점이면 이동 비용이 낮은 쪽, 그다음 `route_id`.
> 이동 비용 대비 효과, 도착지가 실제로 필요한 양, 이동 후 상태, 수요 불확실성을 보지 않는다.

두 방식은 **같은 실행 가능 후보 집합**을 보므로 차이는 순서 규칙에서만 나온다.

## 11. Ablation

각 구성요소의 가중치를 0으로 두고(나머지 재정규화) 같은 후보를 다시 정렬한 결과. 운영 데이터
Top-5 기준.

| 제거한 구성요소 | 가중치 | 1순위 | 순효과 변화 | 부족 충족 변화 |
|---|---:|---|---:|---:|
| 예상 순효과 | 0.276 | 유지 | **−472,024** | +21 |
| 재고 균형 | 0.147 | **변경** | +51,680 | **−33** |
| 이동 부담 | 0.100 | 유지 | +20,160 | −8 |
| 폐기 위험 | 0.125 | 유지 | 0 | 0 |
| 수요 적합도 | 0.114 | 유지 | 0 | 0 |
| 실행 여건 | 0.102 | 유지 | 0 | 0 |
| 수요 안정성 | 0.065 | 유지 | 0 | 0 |
| 이동 후 위험 | 0.071 | 유지 | 0 | 0 |

- **예상 순효과**를 빼면 Top-5의 금액 가치가 47만원 줄어든다. 경제성의 주 동력이 맞다.
- **재고 균형**을 빼면 1순위가 바뀌고 금액은 5만원 늘지만 실제 부족 충족량이 33개 줄어든다.
  이 구성요소가 "장부상 이익"과 "실제 재고 문제 해결"을 저울질하고 있다는 증거다.
- **이동 부담**을 빼면 더 비싼 이동을 고른다.
- 나머지 네 개는 이 데이터의 Top-5를 바꾸지 못했다. **여기서는 효과가 관측되지 않았다**는 뜻으로
  그대로 기록한다. 유지하는 근거는 hard/soft 분리(§3–4)와 극단 시나리오 대응이며, 이 데이터
  하나로 필요성을 주장하지 않는다.

증가분은 후보별 결정 지표(순효과·수량 한계·이동 후 위험·수요 시나리오)를 한 번 계산하는
비용이다. 행 단위 중첩 루프를 추가하지 않았고 기존 벡터화 구조를 유지했다.

운영 검증(`tools/run_operational_validation.py --repeats 3`) 165개 항목 전부 통과.

## 14. 알고리즘 버전

`services/decision_metrics.ALGORITHM_VERSION = "vhs-2.1"`. 구성요소·정규화·hard constraint·
tie-break가 바뀌어 **같은 파일이 다른 순위를 낼 수 있게 되면** 올린다. 결과 객체
(`diagnostics.algorithm_version`, 후보별 `algorithm_version`)와 검증 리포트에 기록되며,
`analysis_timestamp`·`data_signature`와 함께 과거 추천을 재현할 수 있게 한다.
**사용자 기본 화면에는 표시하지 않는다.**

### 이전 구조 → `vhs-2.1` 결과 변화 (익명 운영 데이터)

이전 구조에는 버전 표기가 없었으므로 아래 "이전" 열은 이번 강화 직전에 같은 파일로 측정한 값이다.

| 항목 | 이전 | vhs-2.1 | 사유 |
|---|---|---|---|
| 전체/적용/제외 행 | 2,742 / 2,623 / 119 | 동일 | 데이터 계층 변경 없음 |
| 후보 수 | 62 | 62 | 동일 |
| 추천 가능 | 60 | 58 | 순효과 ≤ 0인 2건이 hard로 차단됨 |
| 이동 불가 | 2 | 4 | 위와 같음 |
| 1순위 | R0050 | R0005 | 아래 참고 |
| 1순위 순효과 | 220,280 | 194,680 | |
| 1순위 안정성 | (후보별 지표 없음) | 안정 (16/16 시나리오 1위) | |
| Pareto front 비율 | 0.26 (5축) | 0.11 (4축) | 축을 줄여 변별력 확보 |

**1순위가 바뀐 이유**: R0050은 순효과가 조금 더 크지만 출발 점포의 이동 가능 재고 184.8개 중
60개(32.5%)만 걷어낸다. R0005는 순효과가 25,600원 적은 대신 이동 가능 재고 71.4개 중 60개
(84%)를 해소하고 도착지 부족량 42개를 전부 채운다. 즉 **장부상 금액이 조금 작은 대신 실제
재고 불균형을 훨씬 많이 해결하는 이동**으로 바뀌었다. Pareto에서 비지배이고, 가중치 섭동
16회 전부에서 1위를 유지한다. Greedy 기준선은 여전히 R0013(금액 최대)을 고르며, 그 후보는
Pareto에서 지배당한다.

## 15. 한계

- **가중치는 학습된 값이 아니다.** 컬럼 커버리지와 변별력에 따른 규칙 기반 배분이며, 정답
  레이블로 최적화한 것이 아니다. 실제 실행 결과가 쌓이기 전에는 최적성을 주장할 수 없다.
- **신뢰도는 성공 확률이 아니다.** 데이터 완전성·실행 가능성·점수 격차·순위 안정성·Pareto·
  Greedy 일치의 상대 지표이며 통계적으로 calibration되지 않았다. 화면은 등급을 먼저 보여준다.
- **비교 대상이 하나다.** 단일 목적 Greedy와만 비교했다. MILP 최적해와의 gap은 측정하지 않았다.
- **Ablation은 데이터 하나에서만 수행했다.** 8개 시나리오는 같은 원본의 변환이라 서로 독립이 아니다.
- **수요 예측은 하지 않는다.** 파일에 있는 수요·표준편차를 그대로 쓴다.
- **DQN은 참고 기능이다.** 학습 데이터가 부족한 현재 상태에서 성능을 주장하지 않으며, 자동
  실행·자동 학습하지 않고 최종 추천을 바꾸지 않는다.
- 폐기 위험·수요 적합도·실행 여건·수요 안정성·이동 후 위험은 이 데이터의 Top-5를 바꾸지
  못했다(§11). 다른 데이터에서의 기여는 별도로 확인해야 한다.
